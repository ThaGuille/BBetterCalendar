# u2 - bbadb.py run-steps (steps runner)

Written afterwards from commit d7954bb (feat run-steps), the skill docs (78f5385) and the repo; the original unit left no note.

- Command: `python .claude/skills/adb-ui-test/scripts/bbadb.py run-steps <file> [--keep-going] [--save <scenario>]`.
  It uses the replay engine without pacing (waits by condition). No .ps1 twin: python also runs on Windows.
- Output: one `[OK  ]` / `[FAIL]` line per step; stops at the first failure after a `<stem>-fail-<n>` capture
  (`--keep-going` runs the rest); `SHEET <png>` (Pillow contact sheet; without Pillow `SHEET none` plus the capture paths);
  last line `run-steps: <ok>/<total> steps ok in <s> s`. Exit 0 all ok, 1 a step failed, 2 missing or empty file.
- `--save` writes the steps to `recordings/<scenario>.log`, replayable with `replay`.
- Files: `.claude/skills/adb-ui-test/scripts/bbadb.py`, `.claude/skills/adb-ui-test/steps/smoke.steps` (GRANT, START,
  ASSERT id=homePlayButton, SHOT, TAP id=navigation_progress, ASSERT id=periodNavTitle; ids only, no language text),
  `.claude/scripts/test/test_run_steps.py` (fake adb, no device).
- Check output (re-run for this note): `python .claude/scripts/test/test_run_steps.py` ends with
  `test-run-steps: all good` (covers the n/n line, exit codes, fail capture, --keep-going, sheet and its fallback,
  --save replayable, missing/empty file).
