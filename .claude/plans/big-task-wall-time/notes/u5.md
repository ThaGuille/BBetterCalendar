# u5 - Gradle daemon memory with two emulators

Written afterwards from commit 61edf27 and `.claude/docs/windows_commands.md` (section "Memory with two emulators (measured 2026-11-13)").

Measurement command (PowerShell, free physical memory):

```powershell
$o=Get-CimInstance Win32_OperatingSystem; 'FreeMB=' + [int]($o.FreePhysicalMemory/1024) + ' TotalMB=' + [int]($o.TotalVisibleMemorySize/1024)
```

Output recorded in the docs, with `emulator-5554` and `emulator-5556` (api36) running on the 31 GB machine:
- about 1.8 GB free (`FreeMB=~1800 TotalMB=32013`);
- a second reading while other builds also ran: `FreeMB=989 TotalMB=32013`.
The exact first reading is approximate in the repo; no other figure is invented here.

Decisions:
- `gradle.properties` now sets `org.gradle.daemon.idletimeout=900000`: an unused Gradle daemon (about 2 GB each,
  `-Xmx2048m` unchanged) exits after 15 min instead of the 3 h default, so parallel units keep memory free.
- Emulator RAM was not lowered: the `bt_quick` snapshot is tied to 3072 MB; another size would invalidate it and force a
  cold boot (~50-60 s) instead of a snapshot load.
- Rule: do not add a third emulator while free memory with two stays under 3 GB.
