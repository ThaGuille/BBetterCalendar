# u7 - replay fixes from the review (F1, F6, F7, F8, F2)

- F1/F6/F7 (`bbadb.py run_step`): `ASSERT id=x expect~=a|b` now polls until the node exists AND its text matches an alternative. The cap is the `WAIT n` before it, else the usual retry budget (4 tries, 1.5 s). A mismatch drops the shared dump (`cache['raw']`) so the next try looks at a fresh one; when the budget ends the failure message is the last dump's `ASSERT failed: id=... expected~='...' but text='...'` (or `not found` if the last try found no node).
- F8 (`run_step` TAP + the WAIT handling of `replay` / `run_steps`): a WAIT before a TAP no longer taps a node of the old screen. If the TAP's target was in the previous dump (kept across the WAIT) or the previous step was a TAP of the same target, the WAIT is slept (capped at n ms) before the tap; when the node was absent, the TAP polls for it as before. A WAIT before an ASSERT still drops the shared dump. `run_step` remembers the last tapped target in the cache dict (`cache['tap']`).
